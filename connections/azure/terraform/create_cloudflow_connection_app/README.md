# Azure CloudFlow Connection Application

This folder contains Terraform configuration to create the Azure resources required by a DoiT CloudFlow Azure connection. It is the Terraform alternative to the `az` CLI script generated by the CloudFlow connection wizard.

## What It Creates

- **Application registration** (`azuread_application`) — the customer-owned Entra ID app that CloudFlow authenticates as
- **Service principal** (`azuread_service_principal`) — the app's identity in the tenant, used as the role assignment principal
- **Federated identity credential** (`azuread_application_federated_identity_credential`, named `doit-cloudflow`) — trusts the DoiT broker service account through workload identity federation, so no client secret is ever created or shared
- **Custom role definition** (`azurerm_role_definition`, optional) — created when both `custom_role_name` and `custom_role_actions` are provided, with `AssignableScopes` limited to the connection scope
- **Role assignments** (`azurerm_role_assignment`) — one per predefined role plus one for the custom role (when present), all at the connection scope

## Required Azure Permissions

The identity running Terraform needs:

- Rights to create application registrations in the tenant (e.g., the **Application Developer** Entra ID role, or the default user consent when app creation is not restricted)
- `Microsoft.Authorization/roleAssignments/write` at the connection scope (e.g., **Owner** or **User Access Administrator** on the target subscription, resource group, or management group)
- `Microsoft.Authorization/roleDefinitions/write` at the connection scope when creating a custom role

## Required Parameters

- `app_display_name`: Display name of the application registration (e.g., `doit-cloudflow-prod`)
- `federation_subject`: Subject of the DoiT broker service account — copy from the CloudFlow connection wizard
- `federation_audience`: Audience of the federated identity credential — copy from the CloudFlow connection wizard (e.g., `api://doit-cloudflow/<customerId>/<connectionId>`)
- `scope_path`: ARM scope where roles are assigned: `/subscriptions/<guid>`, `/subscriptions/<guid>/resourceGroups/<name>`, or `/providers/Microsoft.Management/managementGroups/<id>`

## Optional Parameters

- `federation_issuer`: OIDC issuer trusted by the federated identity credential (default: `https://accounts.google.com`)
- `predefined_roles`: List of Azure built-in role names to assign at the scope (e.g., `["Reader"]`)
- `custom_role_name` and `custom_role_actions`: When both are set, a custom role with those actions is created and assigned at the scope

## Usage Example

```hcl
provider "azurerm" {
  features {}
  subscription_id = "00000000-0000-0000-0000-000000000000"
}

module "cloudflow_connection_app" {
  source = "github.com/doitintl/cloudflow-infra//connections/azure/terraform/create_cloudflow_connection_app"

  app_display_name = "doit-cloudflow-prod"

  federation_subject  = "SUBJECT_FROM_CLOUDFLOW_WIZARD"
  federation_audience = "api://doit-cloudflow/CUSTOMER_ID/CONNECTION_ID"

  scope_path = "/subscriptions/00000000-0000-0000-0000-000000000000"

  predefined_roles = ["Reader"]

  custom_role_name    = "DoiT CloudFlow Connection Role"
  custom_role_actions = ["Microsoft.Compute/virtualMachines/read", "Microsoft.Compute/virtualMachines/start/action"]
}

output "client_id" {
  value = module.cloudflow_connection_app.client_id
}
```

## Notes

- After `terraform apply`, copy the `client_id` output and paste it back into the CloudFlow connection wizard's deploy step to finish creating the connection
- The federated identity credential replaces client secrets entirely: CloudFlow exchanges the DoiT broker identity's token for an app token scoped to this connection's audience, so there is nothing to rotate or leak
- Role assignments (and the optional custom role) are created only at `scope_path`; CloudFlow cannot act outside that scope
